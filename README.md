# Drunkin

Blind-scored tastings with your friends, as a native iPhone app. Everyone scores each pour 1 to 5,
and the table's scores stay hidden until everyone is in. Grew out of the Deer Camp tasting PWA,
rebuilt so it needs **no server, no accounts and no hosting**.

- **Platform:** iOS 17+, iPhone only, SwiftUI, no third-party dependencies
- **Bundle ID:** `fun.dunkin.drunkin`
- **Project:** generated by [XcodeGen](https://github.com/yonaskolb/XcodeGen) from `project.yml`
- **Release:** GitHub Actions → TestFlight → App Store. See [docs/RELEASING.md](docs/RELEASING.md)

## How sharing works without a server

```
           Multipeer Connectivity (Bluetooth / peer-to-peer Wi-Fi, encrypted)
 guest A ───────────────┐
 guest B ─────────────── host phone ── holds every score, decides what each guest may see
 guest C ───────────────┘
                 │
        .drunkin file (AirDrop / Messages) ── results for anyone, or hand-off to a new host
```

- **Live at the table.** The host's phone plays the role the Deer Camp server used to: it holds
  every score and sends each guest only the menu, the roster, *who* has scored, revealed scores
  and that guest's own entries. Guests never receive anyone's hidden score.
- **Joining.** Nearby phones find the host over Bonjour and present the host's 6-digit join
  code. The host issues each phone a 256-bit rejoin token (stored in the guest's Keychain, only
  its SHA-256 on the host) so it reconnects automatically after sleep or walking away.
- **Offline-first.** Every edit is saved on the phone first. Guests keep scoring while the host is
  asleep or out of range; edits sync when they reconnect (last write wins per person per pour, by
  revision counter; host resets bump a generation so stale edits can't come back).
- **After the tasting.** *Share tasting file* exports menu + roster + photos + revealed scores
  only. Anyone can open it in Drunkin as a read-only copy, or host the same menu again.
  *Hand off hosting* exports the full state so another phone can take over.

## Layout

```
Drunkin/
  App/        DrunkinApp.swift (entry, navigation, toasts, file opening)
  Model/      Models, Engine (reveal rules, merge), Results (stats, awards), Sanitize, Templates
  Store/      AppModel (state + persistence + sync glue), Persistence (files, Keychain, secrets), ImageTools
  Sync/       Wire (messages), HostService / GuestService (Multipeer), TastingFile (.drunkin)
  Views/      SwiftUI screens
  Resources/  Assets (icon, logo), PrivacyInfo.xcprivacy
DrunkinTests/ Engine, results and sharing/security tests
docs/         Privacy policy, support page, App Store copy, release guide
```

## Develop

On a Mac with Xcode 26+:

```bash
brew install xcodegen
xcodegen generate
open Drunkin.xcodeproj   # set your Team under Signing & Capabilities to run on a device
```

On Windows: edit, push, and let CI build and test (`.github/workflows/ci.yml`). Multipeer needs
two real devices; use TestFlight builds for that.

## Security notes

- All incoming data (peers and files) is size-capped, decoded with `Codable`, and sanitized:
  strings stripped of control/bidi characters and length-capped, scores clamped 1–5, references
  checked against the roster and menu, collections bounded. Photos are re-encoded through ImageIO
  thumbnailing, which strips EXIF/GPS and avoids decompression bombs.
- Multipeer sessions require encryption. Hosts reject certificates from peers they didn't admit;
  guests only accept the host they invited. Wrong join codes are rate-limited (8 per 5 minutes).
- Join codes and tokens come from the system CSPRNG and are compared in constant time.
- Data at rest uses iOS Data Protection; tokens use `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`.
- No network calls, no analytics, no third-party code. CI actions are pinned to commit SHAs and
  the release job runs behind a protected environment.
